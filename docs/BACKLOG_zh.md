# 自然语言驱动的 S3 数据处理平台：用户故事与验收标准

版本：v1.0  
日期：2026-10-19  
用途：产品 Backlog、开发拆分、测试用例设计与最终项目验收。

本文件依据项目技术测评原文和本次讨论的架构设计编写。原文是需求来源；本文件将其转化为可执行的用户故事与测试条件。本文是需求设计，尚不代表功能已经实现或性能已经测得。

## 1. 范围、角色与标记

### 1.1 角色

- **数据处理用户**：连接自己的 S3，选择文件，配置转换，跟踪任务并查看结果。
- **运维人员**：部署系统、查看任务与资源状态、排查失败。
- **开发者／评审者**：运行代码、验证架构、执行测试和复现性能结果。

用户可以通过匿名会话获得资源归属，不强制实现注册登录。公开部署必须保证不同会话的凭证、任务和结果相互隔离。完整账号系统、组织管理、计费和团队协作不在本次范围。

### 1.2 交付标记

| 标记 | 含义 |
|---|---|
| 必做 | 原文明示，最终交付必须通过 |
| 架构必做 | 原文没有逐字规定，但本方案为可靠性、安全性和可测试性补充的实现约束 |
| 可选 | 产品增强，不影响原文要求的完成判定 |

US-01～US-27 为本方案交付范围；US-28 为可选增强。先完成主流程并不意味着可以省略 Excel、两个额外 LLM 转换、性能验证或公开部署。

### 1.3 共同业务约定

1. **操作种类**：正则替换 `regex_replace`、模式提取 `regex_extract`、数据标准化 `normalize`。后两项是本项目选定的额外 LLM 转换。
2. **输入优先级**：文件、目标列和替换值以用户明确选择的结构化字段为准；自然语言用于描述模式或规则。界面展示最终配置，LLM 不能自行修改这些字段。
3. **原始数据**：处理不覆盖或修改用户 S3 原文件，结果写入平台管理的结果存储。
4. **匹配语义**：替换同一单元格中全部非重叠匹配；替换值按字面文本处理，支持空字符串以删除匹配内容。用户未输入该字段与明确输入空字符串必须区分。
5. **空值语义**：默认保留 null；未匹配的文本保持原样。第一版不接受可能匹配零长度文本的生成模式，并给出可操作的错误。
6. **结果语义**：替换和标准化不改变行数；提取默认增加新列并保留原列。结果分页顺序在同一结果版本内稳定，但不承诺与原 CSV 行序一致。
7. **LLM 边界**：LLM 返回受约束的 JSON 转换计划；系统只执行允许的操作，不执行模型生成的任意代码。默认不发送用户原始数据行给模型。

### 1.4 第一版拟定的可量化门槛

原文要求异步、百万行处理和分页，但没有指定以下数值。这些是本设计提出的初始验收门槛，应在 README 与测试环境中同步记录；不是引用自原文的指标。

| 项目 | 初始门槛 |
|---|---|
| 数据预览 | 最多 100 行 |
| 结果分页 | 默认 100 行，最大 500 行 |
| 任务提交 | HTTP 202；基准环境下 P95 ≤ 2 秒 |
| 进度刷新 | 前端运行时每 2 秒轮询；正常网络下阶段变更 5 秒内可见 |
| 自动尝试 | 暂时性失败最多 3 次尝试，包含首次执行 |
| 正则长度 | 最大 2,048 字符，可配置 |
| 凭证有效期 | 默认 24 小时，可提前断开；到期时拒绝启动新任务 |
| 模型计划缓存 | 默认 24 小时，按用户／会话隔离 |
| 结果保留 | 默认 24 小时，到期返回明确的过期提示 |
| 运行中取消 | 集群正常可达时，60 秒内停止实际计算 |
| 大数据验收 | 至少 3,000,000 行 CSV；时间门槛和资源见 US-25 |

## 3. 详细用户故事与 Acceptance Criteria

下列 AC 使用 Given（前提）／When（操作）／Then（结果）的语义。每条编号可直接作为测试用例或 Jira 子任务的追踪标识。架构验证项需要通过测试、运行记录或代码审查提供证据，不能仅凭页面效果判定通过。

### E1：S3 与文件准备

#### US-01：连接用户自己的 S3

**用户故事**：作为数据处理用户，我希望输入自己的 AWS 凭证与 Bucket 名称建立连接，以便处理我有权访问的数据。

**标记／依赖**：必做；依赖 US-20、US-21 的保护机制。

- **AC-01.1**：给定有效 Access Key、Secret Key 和用户有权访问的 Bucket，提交连接后返回不包含秘密的 `connection_id`，界面显示连接成功。
- **AC-01.2**：给定来自两个不同测试账户、未预先写入平台配置的 Bucket，分别输入其凭证后均能连接；不得依赖固定演示账户或文件。
- **AC-01.3**：缺少必填字段时，前端提示具体字段，后端也独立返回可识别的校验错误，不创建有效连接。
- **AC-01.4**：无效凭证、权限不足、Bucket 不存在、区域不匹配和网络超时分别得到适当错误码与脱敏信息；若上游无法区分“不存在”和“无权限”，明确提示两种可能，不伪造诊断。
- **AC-01.5**：Secret Key 输入框默认隐藏内容；提交过程中有加载状态并阻止重复提交；失败后允许修改并重新连接。
- **AC-01.6**：连接超时有上限；更换 Bucket 或重新连接后，旧文件选择和旧 Schema 被清除，避免跨连接误用。

#### US-02：浏览并选择 S3 文件

**用户故事**：作为数据处理用户，我希望浏览 Bucket 中可用的数据文件，以便选择正确的输入。

**标记／依赖**：必做；依赖 US-01。

- **AC-02.1**：给定有效连接，文件列表展示完整对象 Key、大小和最后修改时间，并能通过前缀浏览子目录。
- **AC-02.2**：当文件数量超过单页上限时，界面可以继续翻页；后端使用 S3 的分页机制，不为返回第一页而读取整个 Bucket。
- **AC-02.3**：第一版支持 `.csv`、`.xlsx`；其他扩展名明确标记为不支持或不可选择。旧版 `.xls` 不作为默认支持承诺，界面与 README 必须一致说明。
- **AC-02.4**：空 Bucket、当前前缀无文件、权限失效和列表请求失败有相应状态；“没有文件”不能与“访问失败”混为一谈。
- **AC-02.5**：用户选择文件时保存完整 Key 和对象版本信息或指纹；提交任务前文件已删除或变化时，提示重新检查，不静默处理另一版本。

#### US-03：异步解析 CSV 与 Excel

**用户故事**：作为数据处理用户，我希望系统识别 CSV 或 Excel 的结构，以便确认文件可用并配置转换。

**标记／依赖**：必做；依赖 US-02、US-11、US-15。

- **AC-03.1**：选中文件并请求检查后，接口立即返回检查任务 ID；下载、解析和 Schema 推断发生在 Celery／Spark 管道中。
- **AC-03.2**：有效 CSV 可读取表头、带引号的分隔符和字段内换行；默认配置为 UTF-8、逗号分隔、首行为表头，用户可明确选择已支持的其他解析选项。
- **AC-03.3**：有效 `.xlsx` 可列出工作表；只有一个可用工作表时可默认选中，存在多个时要求用户选择，随后异步读取其 Schema 和预览。
- **AC-03.4**：CSV 默认以字符串保留值，`00123` 不变成 `123`；其他类型解析策略在预览和文档中明确。非目标列按读取后的 Schema 保留。
- **AC-03.5**：损坏、加密、不支持的编码、超出已公布限制的文件或不可解析行，均给出明确错误；默认严格解析，不悄悄丢弃坏行。
- **AC-03.6**：空文件、有表头但无数据、空 Sheet 分别得到明确结果；重复或空列名必须报错并提示修正，或经用户明确确认后使用可追踪的重命名规则。
- **AC-03.7**：CSV 和 Excel 两条路径最终都形成 PySpark DataFrame；不得只实现浏览器解析或 pandas 全量处理后冒充 Spark 处理。

#### US-04：预览数据并选择目标列

**用户故事**：作为数据处理用户，我希望看到少量样本和列信息，并选择要处理的列，以便避免误操作。

**标记／依赖**：必做；依赖 US-03。

- **AC-04.1**：检查成功后展示列名、解析后的类型和最多 100 行预览；明确说明预览不是完整数据。
- **AC-04.2**：用户可选择一个或多个符合当前操作要求的文本列；缺少目标列时，前后端都禁止创建转换任务。
- **AC-04.3**：数字、日期等列默认不能隐式参与文本替换；如支持转换为字符串，必须让用户明确选择并说明输出类型。
- **AC-04.4**：带空格、中文、点号或反引号的列名可被正确选择与引用，不因列名被解释为表达式而处理错误字段。
- **AC-04.5**：null、空字符串、长文本和可能被浏览器解释为 HTML 的内容均可安全展示；长文本截断不改变后台值。
- **AC-04.6**：切换文件、Sheet 或解析配置后，清除不再适用的预览和目标列，并要求重新确认配置。

### E2：LLM 与数据转换

#### US-05：把自然语言转换为结构化计划

**用户故事**：作为数据处理用户，我希望用自然语言描述模式或规则，以便无需自己编写正则表达式。

**标记／依赖**：必做；依赖 US-06、US-07、US-11。

- **AC-05.1**：给定“查找电子邮件地址”等已支持描述，LLM 返回符合预定义 JSON Schema 的计划，包含操作类型、模式或允许的步骤、必要参数和规则说明。
- **AC-05.2**：针对邮件、订单号和空白清理等固定语义测试集，含义相同的不同表述均通过同一组正反例；不要求生成的正则字符串逐字相同。
- **AC-05.3**：LLM 调用仅发生在 Celery Worker；模型只生成一次列级规则，不对每一行调用模型。
- **AC-05.4**：空输入、超长输入、含义不足、无法支持的转换得到明确提示，不擅自用宽泛模式替换整列。
- **AC-05.5**：不符合 Schema、含任意代码或未知操作的响应不可执行；允许有上限的修复尝试，仍失败时进入可解释的失败状态。
- **AC-05.6**：任务详情展示最终验证通过的规则及说明；模型不能改变用户选择的文件、目标列、替换值或结果归属。

#### US-06：阻止无效或危险的正则

**用户故事**：作为数据处理用户，我希望系统在执行前检查正则，以便错误或高风险模式不会导致失控处理。

**标记／依赖**：必做；依赖 US-05；适用于 US-08、US-09。

- **AC-06.1**：模式必须在与实际 Spark 执行兼容的正则语义下完成编译校验；仅通过 Python `re` 校验不算验收通过。
- **AC-06.2**：无效模式、长度超过 2,048 字符的模式，以及匹配零长度文本的模式，在正式数据转换前被拒绝并返回可识别错误。
- **AC-06.3**：定义并公开支持的正则子集；对嵌套量词、反向引用和其他高风险构造实施限制；`(a+)+$` 等约定危险样例必须被拒绝。
- **AC-06.4**：规则在独立、受时间和资源限制的验证环境中用正例、反例和对抗长文本测试；验证超时不得使 Web 或普通 Celery 控制任务卡死。
- **AC-06.5**：正式 Spark 执行设置时间／资源上限和停止手段；不能将静态黑名单或小样本测试当作不存在回溯风险的证明。
- **AC-06.6**：规则校验失败不发布结果、不进入成功状态，也不写入“验证通过”的 Redis 缓存。
- **AC-06.7**：模型输出中的代码、系统命令、任意函数调用或访问凭证的指令不会被执行。

#### US-07：复用已经验证的 LLM 计划

**用户故事**：作为平台使用者，我希望相同请求复用已有规则，以便减少等待和重复模型调用。

**标记／依赖**：必做；依赖 US-05、US-06。

- **AC-07.1**：相同会话、相同有效输入首次请求调用 LLM；在缓存有效期内再次提交时复用验证通过的计划，模型调用次数不增加。
- **AC-07.2**：缓存键包含操作类型、指令、模型配置版本、Prompt 模板版本、验证器版本和影响结果的列／格式配置；上下文变化不会误命中。
- **AC-07.3**：指令规范化只处理不改变语义的差异；不能通过一律转小写等方法损坏大小写相关的匹配意图。
- **AC-07.4**：过期或失败的计划不被当作成功结果使用；相同缓存键的并发请求有有界去重或锁机制，锁失效可恢复。
- **AC-07.5**：缓存不包含 AWS 凭证或原始数据行，按用户／会话隔离；不得通过缓存响应推断其他会话的私有请求。
- **AC-07.6**：指标可验证命中／未命中；缓存分区暂时不可用时按已记录策略重新生成或清晰失败。若同一 Redis 故障也影响任务投递，则遵循 US-11 的排队恢复策略。

#### US-08：在指定列中替换匹配内容

**用户故事**：作为数据处理用户，我希望把指定列中符合描述的内容替换为指定文本，以便脱敏或清洗数据。

**标记／依赖**：必做；依赖 US-04～US-07、US-16。

- **AC-08.1**：原文三行邮件样例选择 Email 列、替换为 `REDACTED` 后，三行 Email 均为 `REDACTED`，ID 与 Name 保持不变。
- **AC-08.2**：一个单元格包含多个匹配时，全部非重叠匹配均被替换；未匹配部分按原样保留。
- **AC-08.3**：选择多列时，各列使用同一已验证规则处理；未选择列不被修改，行数不变。
- **AC-08.4**：null 保持 null，未匹配字符串保持原样；空字符串遵循不接受零长度匹配模式的约定。
- **AC-08.5**：替换值中的 `$`、反斜杠、中文和引号按字面写入，不被误当作捕获组引用或可执行表达式。
- **AC-08.6**：明确设置空替换值时删除匹配片段；缺失替换字段时校验失败。
- **AC-08.7**：没有任何匹配时任务仍可成功，展示“0 个单元格发生变化”；不把零匹配误报为错误或零行数据。
- **AC-08.8**：输出包含总行数和按列统计的变化单元格数，并说明统计口径；不把变化单元格数标为“匹配次数”。

#### US-09：额外转换一——提取结构化字段

**用户故事**：作为数据处理用户，我希望从文本中提取订单号等信息并写入新列，以便进一步分析。

**标记／依赖**：必做，选定的额外 LLM 转换之一；依赖 US-04～US-07、US-16。

- **AC-09.1**：给定 `Order ORD-123 shipped`，输入“提取 ORD- 后的订单编号”，配置新列 `order_id` 后得到 `ORD-123`；所使用模式由 LLM 计划生成并验证。
- **AC-09.2**：第一版约定提取第一个匹配；无匹配和 null 均写入 null，不产生误导性的空值类型差异；多匹配规则在界面有说明。
- **AC-09.3**：原列和其他字段保持原样，行数不变；新列名与已有列冲突时阻止提交并要求修改。
- **AC-09.4**：提取使用与替换相同的异步提交、计划缓存、正则验证、Spark 执行、进度和分页结果管道。
- **AC-09.5**：正例、反例、多匹配、无匹配、null 和中文上下文均有确定性测试；不能用硬编码样例输出来代替 LLM 规则生成。

#### US-10：额外转换二——文本标准化

**用户故事**：作为数据处理用户，我希望通过自然语言统一文本格式，以便得到可比较的数据。

**标记／依赖**：必做，选定的额外 LLM 转换之二；依赖 US-04、US-05、US-07、US-16。

- **AC-10.1**：第一版支持允许列表中的去除首尾空白、合并连续空白、转小写、转大写，并允许按明确顺序组合。
- **AC-10.2**：输入“去掉首尾空格、把连续空格变成一个、再转小写”，LLM 生成受约束计划；`  ALICE   SMITH  ` 输出 `alice smith`。
- **AC-10.3**：同一个计划内执行顺序确定；重复执行幂等步骤得到相同结果；null 保持 null，未选中列与行数不变。
- **AC-10.4**：请求不支持的语义改写、地址补全或外部数据查询时明确拒绝，不能悄悄改用另一种转换。
- **AC-10.5**：所有步骤映射到批准的 Spark 操作；不在每一行请求模型，不执行 LLM 输出的任意代码。
- **AC-10.6**：任务走完整异步管道，使用计划缓存并显示规则说明；不依赖正则的步骤不强制套用正则校验，但仍通过计划 Schema 与操作允许列表校验。

### E3：异步任务

#### US-11：提交后立即获得任务 ID

**用户故事**：作为数据处理用户，我希望提交请求后立即得到任务编号，以便处理期间继续使用界面。

**标记／依赖**：必做，含可靠投递的架构补充；依赖持久化数据库、Celery、Redis。

- **AC-11.1**：有效请求创建数据库 Job，初始状态为 `QUEUED`，返回 HTTP 202、唯一 `job_id` 和状态查询地址。
- **AC-11.2**：按 US-25 的基准环境进行至少 100 次提交测试、并发 4，P95 响应时间不超过 2 秒；请求不等待 LLM、文件解析或 Spark 完成。
- **AC-11.3**：API 层只做有界校验、资源归属检查和任务记录／投递，不执行重量级数据工作。
- **AC-11.4**：缺少操作、目标列、必要参数，或引用无权访问／过期的连接时，返回 4xx 和稳定错误码，不创建可运行任务。
- **AC-11.5**：同一会话用相同幂等键和相同请求重复提交，返回同一 Job；同一键绑定不同参数时返回冲突错误。
- **AC-11.6**：数据库记录与消息投递之间有可靠恢复机制；模拟提交后 Broker 不可用或进程崩溃，已返回 202 的 Job 不得永久消失或无人调度。
- **AC-11.7**：Celery 消息只包含 Job／连接引用等必要标识，不包含明文凭证、整份数据文件或可执行模型代码。

#### US-12：查看进度并在刷新后恢复

**用户故事**：作为数据处理用户，我希望持续了解任务状态，并在刷新页面后继续查看，以便判断是否需要等待或处理问题。

**标记／依赖**：必做；依赖 US-11、US-21。

- **AC-12.1**：状态至少支持 `QUEUED`、`RUNNING`、`SUCCESS`、`FAILED`；本方案增加终态 `CANCELLED`。状态、阶段、进度及关键时间持久化。
- **AC-12.2**：运行中显示排队、生成计划、验证规则、读入数据、转换、写入结果等阶段；阶段式进度明确标记为估计，不伪称精确行处理比例。
- **AC-12.3**：前端默认每 2 秒轮询，正常网络下后端阶段变化 5 秒内可见；进入终态后停止持续轮询。
- **AC-12.4**：关闭标签页再使用同一有效会话访问任务地址，可恢复当前状态；不依赖浏览器内存保存唯一任务状态。
- **AC-12.5**：短时网络故障显示连接恢复状态并有界退避；不能把一次轮询失败直接当作计算失败。
- **AC-12.6**：只有结果清单和必要元数据提交成功后才能显示 100%／`SUCCESS`；任务重试时显示尝试次数，不能用平滑动画掩盖阶段重跑。
- **AC-12.7**：任务详情可显示创建、开始、结束时间和安全错误信息；Django 重启后已保存的终态与结果引用仍存在。

#### US-13：处理失败、重试与重复执行

**用户故事**：作为数据处理用户，我希望短暂故障可自动恢复，永久失败可清楚解释，以便避免反复盲目提交。

**标记／依赖**：必做；依赖 US-11、US-12、US-17。

- **AC-13.1**：网络超时、上游限流等已定义的暂时性故障采用有界指数退避与抖动，最多 3 次尝试；状态展示当前尝试次数。
- **AC-13.2**：凭证无效、权限不足、损坏文件、非法规则等确定性错误不进行无意义的自动重试。
- **AC-13.3**：超过重试上限后进入 `FAILED`，记录稳定错误码、脱敏信息和可执行建议，不向普通用户暴露完整堆栈或秘密。
- **AC-13.4**：模拟 Worker 被终止、重复消息和消息重新投递，同一 Job 最多发布一个可见的成功结果版本；旧尝试不可覆盖新尝试的终态。
- **AC-13.5**：有心跳／租约或等价机制识别失联任务；恢复调度器对超过已配置阈值的任务进行恢复或失败收敛，不能永久停在 `RUNNING`。
- **AC-13.6**：失败尝试的临时分片不出现在分页结果中，临时资源按可配置策略回收。
- **AC-13.7**：用户修改错误配置后可重新提交新 Job，保留原失败任务记录；重新输入过期凭证时不得悄悄切换为另一文件或账户的数据。

#### US-14：取消排队或运行中的任务

**用户故事**：作为数据处理用户，我希望停止不再需要的处理，以便释放计算资源。

**标记／依赖**：必做；依赖 US-11～US-13、US-16。

- **AC-14.1**：取消排队任务后，该 Job 不再开始数据处理，最终进入 `CANCELLED`。
- **AC-14.2**：取消运行中任务时，API 立即记录取消请求，界面显示“取消中”；状态在实际停止前不伪报 `CANCELLED`。
- **AC-14.3**：集群正常可达时，60 秒内停止关联 Spark 计算／Driver 和仍在等待的任务；取消不能仅修改数据库标记。
- **AC-14.4**：取消控制能够独立于被长任务占用的 Worker 执行；取消接口不等待该长任务自然结束。
- **AC-14.5**：重复取消幂等；已经成功或失败的 Job 返回其终态，不删除已完成结果，不反向修改终态。
- **AC-14.6**：取消与成功同时发生时使用原子终态判定，最终只能有一个终态；取消获胜时不发布结果。
- **AC-14.7**：Worker／集群不可达时展示真实的取消待确认信息并触发恢复机制；取消的尝试不得被自动重试再次启动。

### E4：分布式处理

#### US-15：从 S3 导入 Spark DataFrame

**用户故事**：作为平台使用者，我希望文件进入分布式数据引擎，以便后续操作能够处理大数据。

**标记／依赖**：必做；依赖 US-01～US-03、US-20。

- **AC-15.1**：CSV 和受支持的 Excel 路径均将所选 S3 对象读取为 PySpark DataFrame；使用用户连接的授权上下文。
- **AC-15.2**：有版本号时绑定指定版本；无版本号时使用对象指纹做变化检查。处理中检测到源对象变化时明确失败，不静默接受不可复现输入。
- **AC-15.3**：读取失败、权限失效、缺失工作表、坏行等错误传播到所属 Job，保留可识别阶段和错误码。
- **AC-15.4**：大 CSV 不先完整读入 Django、浏览器或单个 pandas DataFrame；样本预览不触发向 Web 进程传回完整数据。
- **AC-15.5**：每个 Spark 作业使用隔离的连接上下文；两个不同凭证的并发任务不会覆盖共享全局配置而串用账户。
- **AC-15.6**：Excel 导入在异步处理资源内完成，明确内存、文件大小和支持格式限制；不能将百万行 CSV 的测试结果直接宣称为同等规模 Excel 的能力证明。

#### US-16：在多个分区执行转换

**用户故事**：作为平台使用者，我希望转换在 Spark 分区间并行执行，以便数据量增长时仍能完成。

**标记／依赖**：必做；依赖 US-15、US-05～US-10。

- **AC-16.1**：替换、提取、标准化使用批准的 Spark DataFrame 表达式／分布式操作；不在 Driver 中用 Python 逐行循环进行全量转换。
- **AC-16.2**：主转换流程不调用全量 `collect()`／`toPandas()`；小样本与受上限约束的结果页读取需明确边界。
- **AC-16.3**：百万行基准任务实际使用至少两个 Spark Worker、多个有效分区；运行证据包含 Executor／分区信息，不能仅配置多个 Worker 而实际全部单分区运行。
- **AC-16.4**：同一固定数据集在单分区和多分区下输出值、行数、null 处理及统计一致；不能仅通过页面样本推断全量正确性。
- **AC-16.5**：README 解释输入格式、分区大小、并行度、数据倾斜与 Excel 限制的取舍，不强制为所有文件采用同一硬编码分区数。
- **AC-16.6**：Spark 应用／Job Group 与平台 Job 关联，支持进度、故障追踪和真实取消；单个 Job 失败不破坏其他会话的作业。

#### US-17：可靠保存结果并发布清单

**用户故事**：作为数据处理用户，我希望处理完成的结果稳定可读，以便 Web 服务重启后仍能查看。

**标记／依赖**：架构必做；依赖 US-16。

- **AC-17.1**：完整输出写入平台管理的持久化对象／共享存储，主格式为 Parquet；数据库保存结果引用、Schema、行数和清单，不保存百万行数据。
- **AC-17.2**：每次尝试写入独立临时路径；只有所有必要分片写入和校验完成后，才原子发布唯一结果清单并将 Job 标为成功。
- **AC-17.3**：模拟写入中断、Worker 崩溃和重复执行，前端不会读到半成品，成功结果不会被失败尝试覆盖。
- **AC-17.4**：结果清单记录稳定的分片顺序、可分页定位信息、结果版本与过期时间；实际分片布局有大小上限，避免为读取一页扫描全部结果。
- **AC-17.5**：Redis 仅承载控制／缓存信息，不作为完整结果的唯一存储；Web 容器重启后成功结果仍可从持久化存储读取。
- **AC-17.6**：结果到期后接口返回明确的过期错误，清理任务回收相应文件且不影响其他 Job；清理操作可重复执行。

### E5：结果与界面

- **AC-18.7**：分页加载期间界面仍可操作；基准环境中，已完成结果页 API 的 P95 ≤ 2 秒，响应体不超过请求页大小允许的范围。

**用户故事**：作为数据处理用户，我希望在一个清晰流程中完成连接、配置、提交和查看，以便不依赖技术人员操作。

- **AC-19.2**：连接失败、解析失败、LLM 失败、处理失败分别给出可理解的信息与下一步动作，不只显示通用“出错了”。
- **AC-19.3**：加载、排队、重试、取消中、成功、失败、空文件和零匹配状态均有专门显示；长任务期间输入、导航与状态查询不被冻结。

### E6：安全

#### US-20：保护 AWS 凭证及敏感输入

**用户故事**：作为数据处理用户，我希望 AWS 凭证仅用于授权的数据访问，以便安全地使用自己的 Bucket。

**标记／依赖**：必做，含凭证生命周期的架构补充；覆盖整个系统。

- **AC-20.1**：公开环境通过 HTTPS 传输凭证；凭证不进入 URL、浏览器 Local Storage、可分享页面地址或普通 API 响应。
- **AC-20.2**：需要跨异步进程保存的凭证以服务端加密形式保存，解密密钥独立管理；不能把 Base64 或数据库访问权限当作加密。
- **AC-20.3**：使用独特测试秘密进行全链路检查，Web／代理／Celery／Spark／Flower／错误追踪／监控日志、任务参数和响应中均找不到明文秘密；Spark 配置与界面也需要脱敏。

- **AC-20.6**：平台读取用户 Bucket 时不要求写权限，任务完成后原对象内容与元数据保持不变；结果写入使用平台独立授权。
- **AC-20.7**：仓库、镜像、示例配置、录屏和演示数据不包含有效秘密；用户输入的指令和数据内容不作为普通指标标签或未脱敏日志输出。

#### US-21：隔离不同用户或会话的资源

- **AC-21.5**：任务、结果和缓存的过期或清理不破坏其他会话资源；Flower、管理后台、Spark 管理入口不暴露为匿名公共服务。

#### US-23：监控异步任务和 Spark 执行

#### US-24：自动验证关键业务与故障场景

## 4. 状态机与任务接口约定

### 4.1 Job 状态

```text
QUEUED  -> RUNNING -> SUCCESS
                  -> FAILED
                  -> CANCELLED
QUEUED  ----------> CANCELLED
QUEUED  ----------> FAILED   （无法调度且已超过恢复策略）
```

- 重试期间保持 `RUNNING`，以 `stage=RETRYING`、`attempt`、`next_retry_at` 说明等待。
- 取消请求通过 `cancel_requested_at` 和 `stage=CANCELLING` 表示，实际停止后进入 `CANCELLED`。
- 终态不能互相覆盖。用户修正参数后重试是创建新 Job，不修改旧 Job 的输入。
- `progress=100` 仅用于成功且结果已提交；失败／取消保留最后阶段和进度。
- 所有记录包含 `job_id`、资源归属、时间戳；凭证只通过受控引用关联。

### 4.2 建议 API 与对应用户故事

| 方法与路径 | 主要职责 | 故事 |
|---|---|---|
| `POST /api/s3/connections` | 验证并创建连接 | US-01、20、21 |
| `DELETE /api/s3/connections/{id}` | 断开，停止接受新任务 | US-20 |
| `GET /api/s3/connections/{id}/files` | S3 文件列表与游标 | US-02 |
| `POST /api/files/inspect` | 异步检查文件／Sheet | US-03、04 |
| `POST /api/jobs` | 创建处理 Job，返回 202 | US-05～11 |
| `GET /api/jobs/{id}` | 状态、阶段、统计、安全错误 | US-12、13 |
| `POST /api/jobs/{id}/cancel` | 记录取消并停止计算 | US-14 |
| `GET /api/jobs/{id}/results?cursor=...&limit=...` | 读取固定结果版本的一页 | US-18 |
| `POST /api/jobs/{id}/exports` | 可选：创建异步导出 | US-28 |
| `GET /api/exports/{id}` | 可选：查询导出与下载地址 | US-28 |

状态接口建议返回 `status`、`stage`、`progress`、`progress_kind`、`attempt`、`cancel_requested`、`created_at`、`started_at`、`finished_at`、`result_available` 和安全的 `error`。检查任务也必须使用可查询的任务状态，不能另造一个只能等待响应的同步入口。

## 5. 基础验收数据与端到端场景

### 5.1 正则替换固定样例

以下 `null` 表示真正空值，`空字符串` 表示长度为零的字符串。

| ID | 输入 Email／文本 | 替换值 | 预期输出 |
|---|---|---|---|
| 1 | `john.doe@example.com` | `REDACTED` | `REDACTED` |
| 2 | `Contact a@example.com or b@example.org` | `REDACTED` | `Contact REDACTED or REDACTED` |
| 3 | `not-an-email` | `REDACTED` | `not-an-email` |
| 4 | null | `REDACTED` | null |
| 5 | 空字符串 | `REDACTED` | 空字符串 |
| 6 | `a@example.com` | 字面文本 `$1` | 字面文本 `$1` |
| 7 | `Contact a@example.com` | 空字符串 | `Contact ` |

这些样例验证已选中的目标列；另准备未选中但包含相同邮箱的列，验证其不被修改。模型语义测试比较转换结果与正反例，不依赖某条正则的字符串完全相等。
